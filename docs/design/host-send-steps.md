# Host processing steps and original model sends

This opt-in protocol binds one trusted host processing step to its original main send. It does not implement the host processing state machine, acquire a new execution lease, reconcile external effects, or settle money.

A host freezes its processing plan before paid work. A step descriptor contains version 1, a namespace, the plan hash, and a bounded step ID. The existing root provenance remains separate and continues to carry its original attribution. Within that root context, `runtime.host_send_step(session_id, namespace=..., plan_hash=..., step_id=...)` freezes the host descriptor and runtime authority. A model or delegated owner cannot assign a host step. Child sends do not inherit the main step.

`TaskRuntime(..., require_host_send_steps=True)` rejects an external main model send without a step and rejects later changes to that requirement. The default is false for existing SDK hosts. This option is host configuration, not a model tool argument or permission to execute.

Job creation, its original create operation and the step-binding event commit in one TaskRegistry write transaction before provider dispatch. A stable job ID is derived from store, tenant/principal, main session, original root context and the step descriptor. Losing a binding event while its job remains raises `host_send_step_evidence_missing`; it cannot become evidence that the step never ran. Another send index cannot register another job for the same step. An exact original operation replay checks its existing binding and remains a replay, never an implicit new dispatch.

`power_loop.runtime.host_send_steps.lookup(manager, actor, namespace=..., plan_hash=..., step_id=..., expected_host_context=...)` returns the original job/create/binding references. A missing step with no durable job returns None. Existing evidence is checked against actual scope, original root/create hash, descriptor and canonical payload hash. Binding and create payloads have UTF-8 SQL preflight limits of 32 KiB and 64 KiB. These limits do not assert that every pre-existing auxiliary lookup has a global heap bound. The result is historical evidence: execution_authority, resource_stop_confirmed and billing_settled are false.

The host must look up the step before staging input or retrying a loop call. Once a binding exists, use the original job to read its model return receipt or explicitly reconcile/control its pending execution. A create commit with a lost ACK can leave the original job queued and unstarted; it must not be replaced. Model exit, host continuation, external effects, descendant supervision and final business ACK are separate transitions.

The duplicate-dispatch fence runs at model registration. A caller that directly repeats `loop.send` may already have appended transcript input before it reaches that fence. The host still needs original inbox item identities, its own immutable processing plan/phase/effect/finish records and cross-process writer coordination. This API does not promise atomic inbox delivery or grant automatic recovery of an arbitrary old send.

The model return receipt's raw-reference lookup reads metadata columns only; it does not materialize the message body. SQLite and PostgreSQL regressions exercise a 16 MiB unrelated body. Real acceptance uses two distinct logical stages, rejects repeating the first without a provider call, and reads its original binding/result in a fresh mechanical process. Test provider counters distinguish admitted inner calls from requests refused locally; neither is a supplier settlement proof.
